# DeepFish
国际象棋复盘工具。Stockfish 算棋，DeepSeek 把每一步讲成人话。

---
## 代码来源
这个仓库的代码主要由 AI 生成。作者提要求，AI 写，拿它复盘自己的棋，发现讲得不对就追问，然后修改。`src/position.js` 里的纯函数、前端 DOM 操作、一千两百多项测试，大部分来自 AI。

作者负责三件事：
- 明确要什么、不要什么（例如“不要让模型自己算分数”）
- 用工具复盘，发现讲解有误时带着棋谱定位到具体步数和句子
- 对不理解的地方追问到清楚

仓库里的中文注释记录的是“这里为什么非得这么写”。如果也在用 AI 写东西，这个仓库可能比标准开源项目更有参考价值：它记录的是一个不写代码的人带 AI 把想法磨成工具的过程，以及中间遇到的问题。

## 设计原则
所有设计围绕一条原则：

> 引擎和代码负责「是什么」——该走哪步、前后几分、谁在盯着谁、这一步改变了谁的保护。
> 模型只负责「为什么」——把它讲成人话。
>
> 所有数字、格子关系、前后变化，都来自引擎输出或代码按规则复算的结果。模型不自行产生这些内容。讲不清的地方，宁可说“我看不出来”。

这条原则是逐步形成的。后期大部分 bug 表现为“模型讲错了”，查下去多数根因在材料侧：要么没给材料，要么给的材料容易被读反。三个实际例子：

| 它说了什么 | 查下去发现 |
|---|---|
| 样例一第九步，白方 Qd2，“d2 的后和 f4 的象一起盯住了 d6” | 后看不到 d6。那一步是安静着法，没有喂任何材料，模型只能自己推格子关系 |
| 把引擎变化线里的第 5 手说成“眼下的威胁” | PV 给了，但没有说明“这是假想线，只有第 1 手是现在能走的” |
| 样例三第五十步，白方 Kh5，“白王就能 Kxh6 吃掉 h6 的兵” | 材料里没提那个兵——那格被 g7 守着，`Kxh6` 规则上不合法。看着能吃、材料沉默，模型就补上了 |

改这个项目之前，先读 [`项目总结.md`](项目总结.md)。那份文档讲设计、边界、十个坑的根因；这份 README 讲怎么跑、怎么改、怎么自检。

## 运行
### 1. 安装 Node.js
到 [https://nodejs.org/](https://nodejs.org/) 装 LTS 版，在项目目录执行：
```bash
npm install
```

### 2. 放置 Stockfish 引擎
**`stockfish/` 在 gitignore 中**（exe 约 100MB，不进版本库），换机器需要重新放置：
1. 到 [https://stockfishchess.org/download/](https://stockfishchess.org/download/) 下载 Windows x86-64 版
2. 解压，把 exe 放进项目的 `stockfish/` 目录
3. 文件名保持 `stockfish-windows-x86-64-universal.exe`

使用其他版本或路径时，在 `.env` 里写 `STOCKFISH_PATH=...`。

**不放置也能启动。** 服务器启动时会输出黄字警告，界面中“算棋”部分不可用，看棋谱、讲棋照常。

### 3. 配置 DeepSeek 密钥（可选）
不配置也能使用：算棋、曲线、复盘都在，只是没有“让 DeepSeek 讲讲”。
1. 到 [https://platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys) 申请密钥
2. 把 `.env.example` 复制成 `.env`，在 `DEEPSEEK_API_KEY=` 后粘贴
3. 不用重启，刷新页面即可生效
4. 单次消耗 token 很少

后端每次请求会重新检查 `.env` 的修改时间，存盘即生效。这个设计的由来写在 `src/llm.js`：原先只在启动时读一次，导致填了密钥刷新也不生效，界面还没有提示。

### 4. 双击 `start.bat`
它会检查 Node 和依赖、启动服务器，等 `/api/health` 通了再打开浏览器。
**那个黑窗口是服务器本体，关掉即停止服务。**
手动启动：`npm start`，然后打开 [http://localhost:3000](http://localhost:3000)。

> `start.bat` 有两个硬约束：**纯 ASCII + CRLF 换行**。
> 原因写在文件头注释里：中文进入批处理会让 cmd 的行边界错乱，后续行被当作命令执行。仓库里的 `start.bat.broken.bak` 是坏掉的样本可供参考。

## 功能
| 功能 | 说明 |
|---|---|
| 载入棋谱 | 粘 PGN，或者用内置示例：三个小示例（愚人将杀 / 学者将杀 / 歌剧院之局）+ 三个真对局（样例一 / 二 / 三，鼠标停上去能看到各自是什么棋、该看哪一步） |
| 翻页复盘 | 开局 / 上一步 / 下一步 / 结尾，键盘 ←→ Home End，`F` 翻转棋盘 |
| 让鳕鱼分析 | 推荐着法 + 评分 + 候选路线，棋盘上画箭头 |
| 四个显示开关 | 局势条 / 评估曲线 / 每步评分 / 推荐箭头，随开随关 |
| 吃子栏 | 棋盘下面列双方各吃了哪些子，在吃子赚了的那一方标出分差。纯子力账，和引擎无关 |
| 让 DeepSeek 讲讲 | 把当前这一步讲成人话；结尾会多写一行「要点」当这盘棋的记忆（换棋谱清空） |
| 直接在棋盘上走棋 | 走出来的着法记成棋谱的**支线**，可悔棋、可清空、可导出成标准 PGN 变着 |
| 读自带评注的棋谱 | 认得出 lichess 的 `[%eval]` / `[%clk]`，判评（?! ? ??）标在着法列表上 |

## 改完代码后的自检
```bash
npm test            # 四套：不需要服务器、不需要密钥、不花钱
npm run test:llm    # DeepSeek 那条线（本地假服务器，不花钱、不要真密钥）
npm run test:ui     # 把真实网页在 jsdom 里跑一遍（**需要服务器在跑**）
npm run test:all    # 全跑
npm run verify:live # 打一次真的 DeepSeek（配了密钥才有意义，会花几分钱）
```
| 检查 | 管什么 | 项数 |
|---|---|---|
| `verify-pgn.js` | 棋谱解析：带评注的棋谱、无评注 + 升变将杀、变着、NAG、FEN 头、畸形输入、**前后端 chess.js 副本字节一致** | 121 |
| `verify-timeline.js` | 棋子身份时间线：吃子、易位、吃过路兵、升变、坐标翻转 | 56 |
| `verify-engine.js` | 引擎层：UCI 握手、黄金着法、分数视角翻转、将杀、并发队列 | 32 |
| `verify-eval.js` | 评估层：分数归一化、格式化、`/api/evaluate` 批量接口 | 58 |
| `verify-llm.js` | 讲棋那条线：配置、错误分类（401/402/429/超时/断网）、重试、提示词组装、假 DeepSeek 端到端 —— **每条踩过的坑都有断言** | 435 |
| `verify-dom.js` | 真实网页跑在 jsdom 里：棋盘、翻页、分析面板、评注、曲线、局势条、走棋支线、导出、讲解、多轮记忆、吃子栏、样例按钮 | 523 |
一共 **1225 项断言**。
服务器没在跑的时候 `verify-eval.js` 会跳过 16 项，总数显示 1209 —— 这是设计如此，不是坏了。

## 密钥如何避免外泄
浏览器不接触密钥，只与本机后端通信。

```
浏览器  ──►  本机后端（密钥只在这台机器、这个进程的内存中）  ──HTTPS──►  api.deepseek.com
```

`public/` 中没有密钥，也没有直连 DeepSeek 的代码，只请求 `/api/*`。密钥只出现在后端构造请求头的一行 `Authorization: Bearer ***`。

其他约束（在代码中，修改时不要移除）：
- `.env` 被 `.gitignore` 排除在版本库外
- 出站只走请求头，不走 URL，密钥不会留在代理访问日志中
- 上游报错回显会经过 `scrubSecrets()` 清理，防止自建中转在 4xx 中回显 `Authorization` 头
- 给前端的接口（`/api/llm`、`/api/health`、报错体）结构上没有密钥字段，只提供“是否配置”“长度”“打码预览”（`sk-abc****7890`）

这些经过实测：把真密钥读进内存后搜索六个 HTTP 出口的原始响应体，没有命中；另有 `verify-key-safety.js` 模拟反向代理原样回显请求头的情况。
细节在 [`项目总结.md`](项目总结.md) 的“五之二、密钥是怎么关在这台机器里的”。

## 常见问题
**点了“让鳕鱼分析”没反应**
`stockfish/` 里没有那个 exe。看启动时那段黄字警告，按上面第 2 步放好再重启。

**“让 DeepSeek 讲讲”按钮是灰的**
`.env` 里没配密钥，或者密钥无效。改完不用重启，刷新页面即可。
想确认密钥是否通，访问 `/api/llm?probe=1` —— 它会发一个极小的请求去验，花费几乎为零。

**端口被占用（EADDRINUSE）**
已经有一个服务器在跑了（可能是一个没关掉的黑窗口）。先把它关掉。

**关掉黑窗口之后，会不会留下鳕鱼进程？**
不会。实测过：Node 被强杀之后，鳕鱼那边收到 stdin 关闭就自己退了。

**升级了 chess.js 之后要干什么？**
把 `node_modules/chess.js/dist/esm/chess.js` 重新拷到 `public/js/chess.js`。
`verify-pgn.js` 里有一项按**字节**比对这两份，忘了拷会当场报红。
⚠️ 顺手提醒：这件事还有一个更容易中招的变体 —— **换行符**。
git 在 Windows 上默认会把文件转成 CRLF，而 npm 装出来的那份是 LF，
两边一转换字节就对不上了，报错看起来像“你副本拷错了”，其实根本不是。
所以 `.gitattributes` 里给这个文件写了 `-text`（禁止任何换行转换），
`start.bat` 则反过来钉成 `eol=crlf`。**这个文件别删。**
